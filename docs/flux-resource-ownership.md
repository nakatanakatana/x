# Flux resource ownership check

This repository checks whether one cluster resource is produced by more than one Flux owner. The identity is the cluster scope, API group, kind, namespace, and name.

The pull-request check renders every Flux `Kustomization` independently with the Flux CLI and compares the resulting resources. Parent and child `Kustomization` objects are not recursively merged. This keeps the result aligned with the owner that actually applies each path.

The check also supports resources configured individually in a `Kustomization` and resources generated by a `HelmRelease`:

- Kustomization-rendered manifests are read from the output of `flux build kustomization`.
- Helm-generated resources are read from the `HelmRelease` `.status.inventory`.
- Kustomization and HelmRelease Inventory entries are compared using the same resource identity.
- Cluster roots and remote `kubeConfig.secretRef` targets are separate scopes.

## Pull-request check

The GitHub Actions workflow runs the checks in this order:

```sh
# semantic manifest policies
go test ./...

# Flux rendering and ownership
go run ./tests repository --repo-root .

# Flux Schema structural validation
# (run by the configured flux-schema GitHub Action)
```

The repository check exits with status 1 when duplicate ownership is found. It exits with status 2 when a Kustomization cannot be rendered, so an incomplete render does not silently pass the check.

## Runtime check against a cluster

Capture the Flux objects without reading Secret or ConfigMap values:

```sh
kubectl get kustomizations -A -o json > /tmp/flux-kustomizations.json
kubectl get helmreleases -A -o json > /tmp/flux-helmreleases.json
go run ./tests inventory \
  --cluster home \
  --input /tmp/flux-kustomizations.json \
  --input /tmp/flux-helmreleases.json
```

The command can also read a single JSON document from standard input. Run it once per actual cluster scope. For a remote Kustomization, use the target cluster's identifier as `--cluster`; the repository check derives a stable remote scope from the Kustomization path and `kubeConfig.secretRef`.

`HelmRelease` Inventory represents the resources rendered by Helm, including resources that are not present as individual repository manifests. Helm hooks are not part of this comparison, so hook ownership needs a separate review when hooks create persistent resources. See the [Flux HelmRelease documentation](https://fluxcd.io/flux/components/helm/helmreleases/) for the Inventory behavior.

The checker reports owners, not resource contents. A typical collision looks like this:

```text
Duplicate resource ownership detected:
- home/apps/Deployment/apps/web
  - HelmRelease apps/web [status.inventory]
  - Kustomization flux-system/platform [status.inventory]
```

see [Manifest policy testing](manifest-policy-testing.md).
