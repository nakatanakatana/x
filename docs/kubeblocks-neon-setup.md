# KubeBlocks Neon Operations Guide

This guide applies to `Cluster/neon-demo` in the `database` namespace.

`HelmRelease/kubeblocks` and `HelmRelease/neon` in the `kb-system` namespace provide KubeBlocks core and the Neon addon.

The pageserver remote storage endpoint is `http://gateway.pcloud-s3.svc.cluster.local:8080`.

The remote bucket is `neon-demo`, the region is `us-east-1`, and path-style addressing is enabled.

Run the following code blocks in order in the same interactive shell on a trusted administrative workstation.

Do not run credential-loading blocks in shared logs, CI, screen-sharing sessions, or shells with `xtrace` enabled.

Every `kubectl` request has a finite `--request-timeout`.

Wait operations fail if their condition is not satisfied before the deadline.

## Verify the installation

First, verify the Ready conditions of the child Kustomizations for the CRDs and core controller, and of the parent Kustomization that monitors them.

`kubeblocks` depends on `kubeblocks-crds`, and `cluster-controllers` health-checks `kubeblocks`.

```bash
set -euo pipefail

for kustomization in kubeblocks-crds kubeblocks cluster-controllers; do
  ready_status="$(
    kubectl -n flux-system --request-timeout=15s \
      get kustomization/"$kustomization" \
      -o jsonpath='{.status.conditions[?(@.type=="Ready")].status}'
  )"

  if [[ "$ready_status" != "True" ]]; then
    printf 'Kustomization/%s is not Ready: %s\n' \
      "$kustomization" "$ready_status" >&2
    exit 1
  fi
done
```

Next, verify the Ready conditions of both HelmReleases.

```bash
for release in kubeblocks neon; do
  ready_status="$(
    kubectl -n kb-system --request-timeout=15s \
      get helmrelease/"$release" \
      -o jsonpath='{.status.conditions[?(@.type=="Ready")].status}'
  )"

  if [[ "$ready_status" != "True" ]]; then
    printf 'HelmRelease/%s is not Ready: %s\n' "$release" "$ready_status" >&2
    exit 1
  fi
done
```

Then verify the Cluster status and termination policy.

```bash
kubectl -n database --request-timeout=15s \
  get cluster/neon-demo \
  -o jsonpath='{.metadata.name}{" phase="}{.status.phase}{" terminationPolicy="}{.spec.terminationPolicy}{"\n"}'
```

Confirm that the Cluster phase is `Running` and `terminationPolicy` is `Delete`.

Also inspect the generated Pods, PVCs, Services, and gateway endpoints.

```bash
kubectl -n database --request-timeout=15s get pods
kubectl -n database --request-timeout=15s \
  get pvc -l app.kubernetes.io/instance=neon-demo \
  -o custom-columns='NAME:.metadata.name,COMPONENT:.metadata.labels.apps\.kubeblocks\.io/component-name,STORAGE:.spec.resources.requests.storage,CLASS:.spec.storageClassName'
kubectl -n database --request-timeout=15s get services
kubectl -n pcloud-s3 --request-timeout=15s \
  get endpointslice -l kubernetes.io/service-name=gateway
```

Confirm that there are five `rook-ceph-block` PVCs: one 10 GiB pageserver PVC, three 5 GiB safekeeper PVCs, and one 5 GiB compute PVC.

There must be no broker PVC.

`gateway` is a ClusterIP Service selecting the `app=rclone-s3-gateway` Pod in the `pcloud-s3` namespace.

The pinned Neon image contains architecture-sensitive executables. The
validation Cluster therefore sets a cluster-wide
`kubernetes.io/arch: amd64` node selector. All Neon Pods must be scheduled
on AMD64 nodes.

KubeBlocks does not propagate a scheduling-policy change to Components that
are already in a failed state. After merging a cluster-wide placement change,
recreate the validation Cluster using the bounded parent-and-child Flux
suspension procedure in this guide. The recreation deletes the validation
PVCs but retains the pCloud bucket and `Secret/neon-s3-credentials`.

Verify the key names in `neon-s3-credentials`.

```bash
kubectl -n database --request-timeout=15s \
  get secret/neon-s3-credentials \
  -o go-template='{{range $key, $_ := .data}}{{printf "%s\n" $key}}{{end}}' |
  sort
```

The output must contain `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY`.

Verify the gateway's `rclone-s3-credentials` in the same way.

```bash
kubectl -n pcloud-s3 --request-timeout=15s \
  get secret/rclone-s3-credentials \
  -o go-template='{{range $key, $_ := .data}}{{printf "%s\n" $key}}{{end}}' |
  sort
```

The output must contain `PCLOUD_TOKEN`, `RCLONE_AUTH_KEY`, `S3_ACCESS_KEY_ID`, and `S3_SECRET_ACCESS_KEY`.

These commands display only Secret key names, never values.

The Neon chart defines the `cloud_admin` system account, but the full name of the connection Secret generated by KubeBlocks is not fixed in the manifests.

Narrow the candidates by Cluster and component labels, then select exactly one Secret whose current `metadata.name` corresponds to the account.

```bash
cluster_name=neon-demo
compute_component_name=neon-compute
compute_resource_name="${cluster_name}-${compute_component_name}"
account_selector="app.kubernetes.io/instance=${cluster_name},apps.kubeblocks.io/component-name=${compute_component_name}"

mapfile -t account_secrets < <(
  kubectl -n database --request-timeout=15s \
    get secrets -l "$account_selector" \
    -o go-template='{{range .items}}{{printf "%s\n" .metadata.name}}{{end}}' |
    awk '/-account-cloud-admin$/'
)

if (( ${#account_secrets[@]} != 1 )); then
  printf 'Expected one cloud_admin account Secret, found %s\n' \
    "${#account_secrets[@]}" >&2
  exit 1
fi

credential_secret="${account_secrets[0]}"

credential_owner_refs="$(
  kubectl -n database --request-timeout=15s \
    get secret/"$credential_secret" \
    -o go-template='{{range .metadata.ownerReferences}}{{printf "%s/%s\n" .kind .name}}{{end}}'
)"

if [[ $'\n'"$credential_owner_refs"$'\n' != \
  *$'\n'"Component/${compute_resource_name}"$'\n'* ]]; then
  printf '%s\n' \
    'The cloud_admin Secret is not owned by the neon-compute Component' >&2
  exit 1
fi

kubectl -n database --request-timeout=15s \
  get secret/"$credential_secret" \
  -o go-template='{{range $key, $_ := .data}}{{printf "%s\n" $key}}{{end}}' |
  sort
```

The connection Secret output must contain `username` and `password`.

Accept a candidate only when it has the labels for `Cluster/neon-demo` and the `neon-compute` component, and `Component/neon-demo-neon-compute` is present in its owner references.

Discovery and verification use only Secret metadata and key names; they never display values.

## Load cloud_admin credentials interactively

The following code loads credentials into variables in the current interactive shell and checks only the account name and whether the password is empty, without printing credential values.

```bash
set +x

db_user="$(
  kubectl -n database --request-timeout=15s \
    get secret/"$credential_secret" \
    -o jsonpath='{.data.username}' |
    base64 --decode
)"
db_password="$(
  kubectl -n database --request-timeout=15s \
    get secret/"$credential_secret" \
    -o jsonpath='{.data.password}' |
    base64 --decode
)"

if [[ "$db_user" != "cloud_admin" || -z "$db_password" ]]; then
  unset db_user db_password credential_secret credential_owner_refs \
    account_secrets account_selector cluster_name compute_component_name \
    compute_resource_name
  printf '%s\n' 'The generated cloud_admin credentials are invalid' >&2
  exit 1
fi

printf '%s\n' 'The cloud_admin credentials were loaded without printing their values'
unset db_user db_password credential_secret credential_owner_refs \
  account_secrets account_selector cluster_name compute_component_name \
  compute_resource_name
```

Do not pass credentials to `echo`, `printf`, or logs, and do not display the complete Secret with `-o yaml`, `-o json`, or `describe`.

Subsequent PostgreSQL operations use `PGUSER` and `PGPASSWORD` already injected into the compute container, so do not pass locally loaded values as command arguments.

## PostgreSQL smoke test

Select exactly one compute Pod using the KubeBlocks instance label and the component name defined in the Cluster.

```bash
mapfile -t compute_pods < <(
  kubectl -n database --request-timeout=15s \
    get pods \
    -l 'app.kubernetes.io/instance=neon-demo,apps.kubeblocks.io/component-name=neon-compute' \
    -o name
)

if (( ${#compute_pods[@]} != 1 )); then
  printf 'Expected one neon-compute Pod, found %s\n' \
    "${#compute_pods[@]}" >&2
  exit 1
fi

compute_pod="${compute_pods[0]#pod/}"
run_id="$(date -u +%Y%m%d%H%M%S)_$$_${RANDOM}"
table_name="neon_smoke_${run_id}"
expected_value="neon-smoke-${run_id}"
```

Create a uniquely named table, insert one row, and read back the same value.

```bash
actual_value="$(
  kubectl -n database --request-timeout=30s \
    exec -i "$compute_pod" -c neon-compute -- \
    psql -XAtq -h 127.0.0.1 -d postgres \
      -v ON_ERROR_STOP=1 \
      -v table_name="$table_name" \
      -v expected_value="$expected_value" <<'SQL'
CREATE TABLE :"table_name" (value text NOT NULL);
INSERT INTO :"table_name" (value) VALUES (:'expected_value');
SELECT value FROM :"table_name";
SQL
)"

if [[ "$actual_value" != "$expected_value" ]]; then
  printf 'Unexpected smoke-test value: %s\n' "$actual_value" >&2
  exit 1
fi
```

Keep the table until teardown because the restart and recovery tests verify the same row.

Use the following bounded request for subsequent reads.

```bash
read_smoke_value() {
  local actual_value

  actual_value="$(
    kubectl -n database --request-timeout=30s \
      exec -i "$compute_pod" -c neon-compute -- \
      psql -XAtq -h 127.0.0.1 -d postgres \
        -v ON_ERROR_STOP=1 \
        -v table_name="$table_name" <<'SQL'
SELECT value FROM :"table_name";
SQL
  )"

  if [[ "$actual_value" != "$expected_value" ]]; then
    printf 'Unexpected smoke-test value: %s\n' "$actual_value" >&2
    return 1
  fi
}
```

## Verify objects in pCloud

The rclone configuration in the gateway Pod authenticates to pCloud using environment variables injected into the Pod.

The following function obtains the Pod name from its label.

```bash
get_gateway_pod() {
  local -a gateway_pods

  mapfile -t gateway_pods < <(
    kubectl -n pcloud-s3 --request-timeout=15s \
      get pods -l app=rclone-s3-gateway -o name
  )

  if (( ${#gateway_pods[@]} != 1 )); then
    printf 'Expected one rclone gateway Pod, found %s\n' \
      "${#gateway_pods[@]}" >&2
    return 1
  fi

  printf '%s\n' "${gateway_pods[0]#pod/}"
}
```

Wait up to 10 minutes for an object to appear in the remote bucket.

```bash
gateway_pod="$(get_gateway_pod)"
object_deadline=$((SECONDS + 600))
first_object=""

while (( SECONDS < object_deadline )); do
  if first_object="$(
    kubectl -n pcloud-s3 --request-timeout=30s \
      exec "$gateway_pod" -c rclone -- \
      sh -c 'rclone lsf pcloud:buckets/neon-demo --recursive | head -n 1'
  )" && [[ -n "$first_object" ]]; then
    break
  fi

  if (( SECONDS >= object_deadline )); then
    break
  fi

  sleep 5
done

if [[ -z "$first_object" ]]; then
  printf '%s\n' \
    'Timed out waiting for Neon objects in the neon-demo bucket' >&2
  exit 1
fi

printf '%s\n' "$first_object"
```

Recursive listing stops after the first object.

The output contains only one object name and does not include the pCloud token or S3 credentials.

## Read after restarting the pageserver

The following function selects the current pageserver Pod by label, deletes it, and waits up to 10 minutes for the replacement Pod with the same name to become Ready.

```bash
restart_pageserver() {
  local -a pageserver_pods
  local pageserver_pod
  local restart_deadline
  local ready_status

  mapfile -t pageserver_pods < <(
    kubectl -n database --request-timeout=15s \
      get pods \
      -l 'app.kubernetes.io/instance=neon-demo,apps.kubeblocks.io/component-name=neon-pageserver' \
      -o name
  )

  if (( ${#pageserver_pods[@]} != 1 )); then
    printf 'Expected one neon-pageserver Pod, found %s\n' \
      "${#pageserver_pods[@]}" >&2
    return 1
  fi

  pageserver_pod="${pageserver_pods[0]#pod/}"

  kubectl -n database --request-timeout=2m \
    delete pod/"$pageserver_pod" --wait=true --timeout=2m

  restart_deadline=$((SECONDS + 600))
  ready_status=""

  while (( SECONDS < restart_deadline )); do
    if ready_status="$(
      kubectl -n database --request-timeout=15s \
        get pod/"$pageserver_pod" \
        -o jsonpath='{.status.conditions[?(@.type=="Ready")].status}' \
        2>/dev/null
    )" && [[ "$ready_status" == "True" ]]; then
      break
    fi

    if (( SECONDS >= restart_deadline )); then
      break
    fi

    sleep 5
  done

  if [[ "$ready_status" != "True" ]]; then
    printf '%s\n' 'Timed out waiting for the replacement pageserver Pod' >&2
    return 1
  fi
}
```

Restart the pageserver and read the stored value again.

```bash
restart_pageserver
read_smoke_value
```

## Behavior and recovery while the gateway is stopped

Do not perform writes during this test.

The durability of new writes cannot be assumed while the gateway, which uses a write-back cache, is stopped.

Register cleanup that restores the gateway to one replica even after an abnormal exit, then scale the Deployment down to zero replicas.

```bash
restore_gateway() {
  kubectl -n pcloud-s3 --request-timeout=15s \
    scale deployment/rclone-s3-gateway --replicas=1
  kubectl -n pcloud-s3 --request-timeout=10m \
    rollout status deployment/rclone-s3-gateway --timeout=10m
}

gateway_restored=false

cleanup_gateway() {
  if [[ "$gateway_restored" != "true" ]]; then
    restore_gateway || true
  fi
}

trap cleanup_gateway EXIT INT TERM

kubectl -n pcloud-s3 --request-timeout=15s \
  scale deployment/rclone-s3-gateway --replicas=0
kubectl -n pcloud-s3 --request-timeout=5m \
  rollout status deployment/rclone-s3-gateway --timeout=5m
```

Record the exit status and output of an attempt to read the existing table in a local file.

```bash
outage_log="neon-gateway-outage-${run_id}.log"

set +e
kubectl -n database --request-timeout=30s \
  exec -i "$compute_pod" -c neon-compute -- \
  psql -XAtq -h 127.0.0.1 -d postgres \
    -v ON_ERROR_STOP=1 \
    -v table_name="$table_name" <<'SQL' >"$outage_log" 2>&1
SELECT value FROM :"table_name";
SQL
outage_status=$?
set -e

printf 'gateway-outage exit status: %s\n' "$outage_status" |
  tee -a "$outage_log"
```

The cached read may succeed, or it may fail because remote storage is unavailable.

Record either outcome in `outage_log` together with the exit status.

Do not infer the presence or absence of data loss from this single observation.

Restore the gateway and retry the read.

```bash
restore_gateway
gateway_restored=true
trap - EXIT INT TERM

kubectl -n pcloud-s3 --request-timeout=15s \
  get endpointslice -l kubernetes.io/service-name=gateway

if ! read_smoke_value; then
  restart_pageserver
  read_smoke_value
fi
```

## Rotate S3 credentials

First update `S3_ACCESS_KEY_ID` and `S3_SECRET_ACCESS_KEY` in the `pcloud-s3` item in 1Password.

Do not print the new values to the terminal, Git, or external logs.

The gateway and pageserver read credentials from environment variables, so synchronize the ExternalSecrets in both namespaces before restarting them.

The following function records the refresh time before synchronization and waits up to 10 minutes for a new refresh time and `Ready=True`.

```bash
refresh_external_secret() {
  local namespace="$1"
  local name="$2"
  local previous_refresh_time
  local current_refresh_time
  local ready_status
  local rotation_status
  local refresh_deadline

  previous_refresh_time="$(
    kubectl -n "$namespace" --request-timeout=15s \
      get externalsecret/"$name" \
      -o jsonpath='{.status.refreshTime}'
  )"

  kubectl -n "$namespace" --request-timeout=15s \
    annotate externalsecret/"$name" \
    force-sync="$(date +%s%N)" --overwrite

  refresh_deadline=$((SECONDS + 600))
  current_refresh_time="$previous_refresh_time"
  ready_status=""

  while (( SECONDS < refresh_deadline )); do
    if rotation_status="$(
      kubectl -n "$namespace" --request-timeout=15s \
        get externalsecret/"$name" \
        -o jsonpath='{.status.refreshTime}{"|"}{.status.conditions[?(@.type=="Ready")].status}'
    )"; then
      current_refresh_time="${rotation_status%%|*}"
      ready_status="${rotation_status#*|}"

      if [[ -n "$current_refresh_time" \
        && "$current_refresh_time" != "$previous_refresh_time" \
        && "$ready_status" == "True" ]]; then
        break
      fi
    fi

    if (( SECONDS >= refresh_deadline )); then
      break
    fi

    sleep 5
  done

  if [[ -z "$current_refresh_time" \
    || "$current_refresh_time" == "$previous_refresh_time" \
    || "$ready_status" != "True" ]]; then
    printf 'Timed out waiting for ExternalSecret/%s in %s\n' \
      "$name" "$namespace" >&2
    return 1
  fi
}
```

After confirming both synchronizations, restart the gateway and pageserver and read the stored value.

```bash
refresh_external_secret pcloud-s3 rclone-s3-credentials
refresh_external_secret database neon-s3-credentials

kubectl -n pcloud-s3 --request-timeout=15s \
  rollout restart deployment/rclone-s3-gateway
kubectl -n pcloud-s3 --request-timeout=10m \
  rollout status deployment/rclone-s3-gateway --timeout=10m

restart_pageserver
read_smoke_value
```

Status checks read only ExternalSecret timestamps and conditions; they do not display Secret values.

## One-time recreation of the safekeeper ComponentDefinition

Because `ComponentDefinition.spec.runtime` is immutable, the post-rendered security context cannot be applied to the existing `ComponentDefinition/neon-safekeeper-1.0.1`.

Use this procedure once after merging the fix to recreate the current validation `Cluster/neon-demo` and the existing ComponentDefinition.

Recreation deletes the Neon PVCs in Kubernetes.

It does not delete the `neon-demo` bucket in pCloud or the manually created `Secret/neon-s3-credentials` in the `database` namespace.

First verify that retained resources exist and check the Cluster termination policy.

```bash
set -euo pipefail

kubectl -n database --request-timeout=15s \
  get secret/neon-s3-credentials -o name

gateway_pod="$(get_gateway_pod)"
kubectl -n pcloud-s3 --request-timeout=30s \
  exec "$gateway_pod" -c rclone -- \
  rclone lsd pcloud:buckets |
  awk '$NF == "neon-demo" {found=1} END {exit !found}'

policy="$(
  kubectl -n database --request-timeout=15s \
    get cluster/neon-demo -o jsonpath='{.spec.terminationPolicy}'
)"

if [[ "$policy" != "Delete" ]]; then
  printf 'Refusing recreation: expected terminationPolicy Delete, got %s\n' \
    "$policy" >&2
  exit 1
fi

mapfile -t neon_pvcs < <(
  kubectl -n database --request-timeout=15s \
    get pvc -l app.kubernetes.io/instance=neon-demo -o name
)

if (( ${#neon_pvcs[@]} != 5 )); then
  printf 'Expected five neon-demo PVCs before recreation, found %s\n' \
    "${#neon_pvcs[@]}" >&2
  exit 1
fi
```

To prevent Flux from recreating the Cluster during the procedure, suspend the
parent `Kustomization/cluster-controllers` first, then suspend the child
`Kustomization/cluster-resources`.

If the parent is not suspended, its reconciliation can restore the child's
`spec.suspend` to the value in Git and recreate the Cluster during deletion.

If a command fails after suspension, the EXIT trap resumes only these two
Kustomizations.

Cleanup preserves the original exit status even if resuming fails, so it does not hide the first failure.

```bash
cluster_reconciliation_resumed=false

resume_cluster_reconciliation() {
  local resume_failed=false

  kubectl -n flux-system --request-timeout=15s \
    patch kustomization/cluster-resources \
    --type=merge --patch='{"spec":{"suspend":false}}' \
    || resume_failed=true
  kubectl -n flux-system --request-timeout=15s \
    patch kustomization/cluster-controllers \
    --type=merge --patch='{"spec":{"suspend":false}}' \
    || resume_failed=true

  [[ "$resume_failed" == "false" ]]
}

resume_cluster_reconciliation_on_exit() {
  local original_status=$?

  trap - EXIT
  if [[ "$cluster_reconciliation_resumed" != "true" ]]; then
    if ! resume_cluster_reconciliation; then
      printf '%s\n' \
        'Failed to resume Neon cluster reconciliation during cleanup' >&2
    fi
  fi

  return "$original_status"
}

trap resume_cluster_reconciliation_on_exit EXIT

kubectl -n flux-system --request-timeout=15s \
  patch kustomization/cluster-controllers \
  --type=merge --patch='{"spec":{"suspend":true}}'
kubectl -n flux-system --request-timeout=15s \
  patch kustomization/cluster-resources \
  --type=merge --patch='{"spec":{"suspend":true}}'

controllers_suspended="$(
  kubectl -n flux-system --request-timeout=15s \
    get kustomization/cluster-controllers -o jsonpath='{.spec.suspend}'
)"
resources_suspended="$(
  kubectl -n flux-system --request-timeout=15s \
    get kustomization/cluster-resources -o jsonpath='{.spec.suspend}'
)"

if [[ "$controllers_suspended" != "true" \
  || "$resources_suspended" != "true" ]]; then
  printf '%s\n' 'Neon cluster reconciliation was not suspended' >&2
  exit 1
fi
```

Next, delete the fixed-name validation Cluster and wait up to 10 minutes for the Cluster and recorded PVCs to disappear.

```bash
kubectl -n database --request-timeout=30s \
  delete cluster/neon-demo --wait=false
kubectl -n database --request-timeout=10m \
  wait --for=delete cluster/neon-demo --timeout=10m

pvc_deadline=$((SECONDS + 600))
remaining_pvcs=("${neon_pvcs[@]}")

while (( SECONDS < pvc_deadline && ${#remaining_pvcs[@]} > 0 )); do
  next_remaining_pvcs=()

  for pvc in "${remaining_pvcs[@]}"; do
    pvc_state="$(
      kubectl -n database --request-timeout=15s \
        get "$pvc" --ignore-not-found=true -o name
    )"
    if [[ -n "$pvc_state" ]]; then
      next_remaining_pvcs+=("$pvc")
    fi
  done

  remaining_pvcs=("${next_remaining_pvcs[@]}")
  if (( ${#remaining_pvcs[@]} > 0 )); then
    sleep 5
  fi
done

if (( ${#remaining_pvcs[@]} != 0 )); then
  printf 'Timed out waiting for PVC removal: %s\n' \
    "${remaining_pvcs[*]}" >&2
  exit 1
fi
```

After deleting the Cluster, delete the fixed-name safekeeper ComponentDefinition.

Reconcile the HelmRelease with a deadline to recreate the ComponentDefinition with the post-render patch.

```bash
kubectl --request-timeout=30s \
  delete componentdefinition/neon-safekeeper-1.0.1 --wait=false
kubectl --request-timeout=5m \
  wait --for=delete componentdefinition/neon-safekeeper-1.0.1 --timeout=5m

flux reconcile helmrelease neon \
  --namespace=kb-system \
  --force \
  --with-source \
  --timeout=10m

kubectl -n kb-system --request-timeout=10m \
  wait helmrelease/neon --for=condition=Ready --timeout=10m

safekeeper_security_context="$(
  kubectl --request-timeout=15s \
    get componentdefinition/neon-safekeeper-1.0.1 \
    -o jsonpath='{.spec.runtime.securityContext.fsGroup}{" "}{.spec.runtime.securityContext.fsGroupChangePolicy}'
)"

if [[ "$safekeeper_security_context" != "996 OnRootMismatch" ]]; then
  printf 'Unexpected safekeeper security context: %s\n' \
    "$safekeeper_security_context" >&2
  exit 1
fi
```

After verifying the ComponentDefinition, confirm again that retained resources still exist.

```bash
kubectl -n database --request-timeout=15s \
  get secret/neon-s3-credentials -o name

gateway_pod="$(get_gateway_pod)"
kubectl -n pcloud-s3 --request-timeout=30s \
  exec "$gateway_pod" -c rclone -- \
  rclone lsd pcloud:buckets |

```

Finally, resume the child `Kustomization/cluster-resources` and then the parent
`Kustomization/cluster-controllers`, allowing Flux to recreate
`Cluster/neon-demo`.

```bash
resume_cluster_reconciliation
cluster_reconciliation_resumed=true
trap - EXIT

flux reconcile kustomization cluster-controllers \
  --namespace=flux-system \
  --with-source \
  --timeout=10m
flux reconcile kustomization cluster-resources \
  --namespace=flux-system \
  --with-source \
  --timeout=10m

kubectl -n flux-system --request-timeout=10m \
  wait kustomization/cluster-resources \
  --for=condition=Ready --timeout=10m
kubectl -n database --request-timeout=20m \
  wait cluster/neon-demo \
  --for=jsonpath='{.status.phase}'=Running --timeout=20m
```

This procedure does not modify the bucket, `Secret/neon-s3-credentials`, chart version, or CRDs.

## Delete the Cluster while retaining the remote bucket

If only the Cluster is deleted while Flux manages `clusters/home/resources/neon-demo.yaml`, it will be recreated during the next reconciliation.

First inspect the active termination policy and record the PVC names to be deleted.

```bash
policy="$(
  kubectl -n database --request-timeout=15s \
    get cluster/neon-demo -o jsonpath='{.spec.terminationPolicy}'
)"

if [[ "$policy" != "Delete" ]]; then
  printf 'Refusing teardown: expected terminationPolicy Delete, got %s\n' \
    "$policy" >&2
  exit 1
fi

mapfile -t neon_pvcs < <(
  kubectl -n database --request-timeout=15s \
    get pvc -l app.kubernetes.io/instance=neon-demo -o name
)

if (( ${#neon_pvcs[@]} != 5 )); then
  printf 'Expected five neon-demo PVCs before teardown, found %s\n' \
    "${#neon_pvcs[@]}" >&2
  exit 1
fi

broker_pvcs="$(
  kubectl -n database --request-timeout=15s \
    get pvc \
    -l 'app.kubernetes.io/instance=neon-demo,apps.kubeblocks.io/component-name=neon-broker' \
    -o name
)"

if [[ -n "$broker_pvcs" ]]; then
  printf 'Unexpected broker PVCs: %s\n' "$broker_pvcs" >&2
  exit 1
fi
```

Next, an operator removes `clusters/home/resources/neon-demo.yaml` from the desired state in Git, commits the change, and pushes it.

```bash
git rm clusters/home/resources/neon-demo.yaml
git commit -m "chore: remove neon demo cluster"
git push

flux reconcile kustomization cluster-resources \
  --namespace=flux-system \
  --with-source \
  --timeout=10m

kubectl -n flux-system --request-timeout=5m \
  wait kustomization/cluster-resources \
  --for=condition=Ready --timeout=5m
```

An operator authorized to delete the Cluster must review and perform the commit and push.

Proceed to deletion verification only after both the bounded reconciliation and Ready check succeed.

Wait up to 10 minutes each for Cluster deletion and PVC deletion.

```bash
kubectl -n database --request-timeout=10m \
  wait --for=delete cluster/neon-demo --timeout=10m

pvc_deadline=$((SECONDS + 600))
remaining_pvcs=("${neon_pvcs[@]}")

while (( SECONDS < pvc_deadline && ${#remaining_pvcs[@]} > 0 )); do
  next_remaining_pvcs=()

  for pvc in "${remaining_pvcs[@]}"; do
    if pvc_state="$(
      kubectl -n database --request-timeout=15s \
        get "$pvc" --ignore-not-found=true -o name
    )"; then
      if [[ -n "$pvc_state" ]]; then
        next_remaining_pvcs+=("$pvc")
      fi
    else
      next_remaining_pvcs+=("$pvc")
    fi
  done

  remaining_pvcs=("${next_remaining_pvcs[@]}")

  if (( SECONDS >= pvc_deadline )); then
    break
  fi

  sleep 5
done

if (( ${#remaining_pvcs[@]} != 0 )); then
  printf 'Timed out waiting for PVC removal: %s\n' \
    "${remaining_pvcs[*]}" >&2
  exit 1
fi
```

Finally, confirm that the `neon-demo` bucket remains in pCloud without displaying credentials.

```bash
gateway_pod="$(get_gateway_pod)"

kubectl -n pcloud-s3 --request-timeout=30s \
  exec "$gateway_pod" -c rclone -- \
  rclone lsd pcloud:buckets |
  awk '$NF == "neon-demo" {found=1} END {exit !found}'
```

If the final command succeeds, the remote `neon-demo` bucket remains.

`Delete` removes Kubernetes resources for the validation Cluster; unlike `WipeOut`, it does not erase external storage.
